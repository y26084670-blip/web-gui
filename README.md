# Clark UI Editor

Обновлено: 2026-09-06 17:30 UTC.

Clark UI Editor — браузерное приложение для выбора базового каталога проектов, 
проекта и задания, чтения файлов из input3XX, редактирования скаляров и массивов, 
операций над записями и строками, проверки ограничений, прикладной диагностики 
и сохранения исходных данных. Приложение собирается Vite и работает полностью 
на стороне браузера.

Перед записью модели редактор создаёт `input3XX/_nogo.e3d`. Маркер удаляется
только после полного сохранения и новой проверки без ошибок; его наличие
предупреждает решатель о неподтверждённых исходных данных, но не блокирует расчёт.

## Требования

Для сборки и разработки:

- Node.js 24; состав и диапазоны зависимостей заданы в
  [package.json](package.json), точные версии дерева — в
  [package-lock.json](package-lock.json).

Для работы редактора на клиентском компьютере:

- актуальный Google Chrome Desktop или Microsoft Edge Desktop;
- безопасный контекст: localhost либо HTTPS;
- разрешение пользователя на чтение и запись выбранного локального каталога.

Отдельный Chromium SDK на клиентском компьютере не устанавливается: необходимые
Web API предоставляет поддерживаемый браузер. Firefox и Safari не поддерживают
требуемый редактору доступ к локальному каталогу. Работа других браузеров на
основе Chromium проектом не подтверждена.

Перед открытием системного файлового диалога редактор проверяет безопасный
контекст и наличие необходимых методов File System Access API. Если условия не
выполнены, вместо последующей технической ошибки показывается сообщение с
требованиями к браузеру и адресу.

В обычном режиме необходимо выбирать корневой каталог с точным именем
`clark.projects`. Он может находиться на любом диске и на любой глубине.
Сеансовый режим администратора снимает только это ограничение имени.

Установка зависимостей из корня репозитория. Выполняет «чистую установку» зависимостей 
проекта строго по package-lock.json, удаляя существующую папку node_modules и гарантируя 
воспроизводимость окружения. Это быстрее и надёжнее, чем npm install.

~~~bat
npm ci
~~~

Подробное сравнение режимов разработки и релиза, последовательность сборки,
варианты запуска и типовые расхождения описаны в
[справочнике по сборке и выполнению](docs/BUILD_AND_RUNTIME.md).

## Установка примеров

Откройте «Общая информация» кнопкой `?` и нажмите «Развернуть примеры».
Если адрес архива ещё не настроен, введите прямую ссылку на ZIP. Выберите папку,
в которой нужно создать `clark.projects`, или существующий `clark.projects`.
Дождитесь загрузки и распаковки, затем выберите этот каталог в редакторе.

Архив размещается отдельно и может содержать одновременно legacy-задания,
актуальные задания и результаты расчётов. Они копируются без преобразования.
Существующие файлы пропускаются. При отмене уже записанные файлы остаются;
повторная установка допишет недостающие файлы.

URL по умолчанию задаётся в `public/examples-config.json` перед сборкой либо
в `examples-config.json` готового сайта. Пока архив не подготовлен, поле `url`
остаётся пустым. Требования к ссылке, архиву и серверу описаны в
[справочнике по сборке и выполнению](docs/BUILD_AND_RUNTIME.md#внешний-архив-примеров).

## Сборка и запуск для отладки

Отдельный debug-bundle в dist/ не создаётся. Для разработки используется Vite
dev server:

~~~bat
npm run dev
~~~

На Windows можно запустить [scripts/dev.cmd](scripts/dev.cmd). Сценарий при
необходимости выполняет npm ci, затем запускает dev server и открывает браузер:

~~~bat
scripts/dev.cmd
~~~

## Сборка для релиза

Production-сборка создаётся в каталоге `dist`:

~~~bat
npm run build:release
~~~

Команда npm run build также выполняет production-сборку. Для GitHub Pages
используется отдельный base path:

~~~bat
npm run build:pages
~~~

Автоматическая публикация Pages описана в
[.github/workflows/deploy-pages.yml](.github/workflows/deploy-pages.yml).

## Запуск готовой сборки

Локальная проверка уже созданного `dist`:

~~~bat
npm run preview
~~~

Локальная release-сборка на Windows с чистой установкой зависимостей:

~~~bat
scripts/build-local.cmd
~~~

Сценарий выполняет `npm ci` и `npm run build:release`.

Перед первым развёртыванием в локальной сети нужно установить Caddy
(сценарий использует winget):

~~~bat
scripts/caddy/install.cmd
~~~

Сборка и запуск release-варианта для локальной сети:

~~~bat
scripts/release-lan.cmd
~~~

Связанные сценарии находятся в [scripts/caddy/](scripts/caddy/), а конфигурация
сервера — в [deploy/caddy/Caddyfile](deploy/caddy/Caddyfile). LAN-сценарий
рассчитан на Windows, PowerShell, Caddy и частный сетевой профиль Windows.

## Тесты

Существующие тесты находятся в [test/](test/) и при необходимости запускаются
отдельно, без браузера:

~~~bat
npm test
~~~

Команда выполняет `node --test`. Запуск и состав проверок выбираются по риску
конкретного изменения; тестирование не является обязательным этапом каждой
правки. Локальные сценарии сборки и автоматическая публикация тесты не запускают.
В GitHub Actions их можно включить параметром `run_tests` при ручном запуске
workflow `Build editor and agent fallback`; по умолчанию параметр выключен.
Подготовка и проверка комплектности базовых библиотек при сборке сохраняются.
Текущее подтверждённое состояние проверок зафиксировано в
[docs/resume.md](docs/resume.md).

Архитектурный контракт находится в
[docs/Architecture.md](docs/Architecture.md), порядок внесения изменений — в
[docs/IMPLEMENTATION_PROTOCOL.md](docs/IMPLEMENTATION_PROTOCOL.md), текущее
состояние и открытые работы — в [docs/resume.md](docs/resume.md).

## Локальный помощник

Редактор содержит встроенные базовые рекомендации и 18 тем справки. Отдельный
clark.agent подключается дополнительно; его отсутствие не блокирует работу.
Подсказки не выполняют команды изменения модели. Для локального подключения
используются WebSocket и ключ редактора, полученный на странице настройки агента.

Сценарии запуска и ограничения: [локальная интеграция](docs/AGENT_INTEGRATION.md).
