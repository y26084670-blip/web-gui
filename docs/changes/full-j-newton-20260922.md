# fullJNewton — изменение конфигурации модели

Дата: 2026-09-22. Версия исходников редактора: 4.26.0.
Основание: согласованный план владельца для solver и web-gui.

## Изменение

В `src/services/schemas/conrab.schema.js` после CF_KEPS добавлена последняя
строка `fullJNewton — полный Newton [J/λ]`. Это обычное хранимое Boolean-поле
с default=false. Штатный форматтер показывает «Полный Newton» для true и
«Упрощённый Newton» для false с существующими маркерами логического состояния.
Полный текст подсказки хранится в description этой строки и поясняет методы,
обязательный полный режим ВТСП, независимость от htcRo и выбор профиля.

Теперь каждая сохраняемая запись conrab.txt содержит 14 актуальных полей.
Ранее указанное в AI_CLARK_INTEGRATION.md количество 13 относится к версии
без fullJNewton; этот датированный файл фиксирует изменение формата.
Сам двухстрочный формат Float32 → Float64 не изменяется. Настройка действует
отдельно в каждой профильной колонке. Обычные сериализация, история изменений
и выбор активной разрядности используются без новой отдельной модели состояния.
Отсутствующее поле получает false через существующий механизм defaults;
явные false/true сохраняются. Новых method/useFullJNewton в JSON нет.

Для обычных линейных проводников false выбирает локальную 3x3/Schur-коррекцию,
true — полный токовый Newton/GMRES. При наличии ВТСП в неизвестной токовой
системе полный метод обязателен для всей системы независимо от значения флага.
GUI не переписывает заданное значение в true по материалам. Математический
контракт принадлежит solver: `docs/AI_CURRENT_NEWTON_MODES.md` и реализация Ist.

Старые executable с проверкой фиксированного набора Conrab могут отвергнуть
новый ключ. Сохранённые новым GUI задания необходимо использовать с решателем,
поддерживающим fullJNewton. Обновление Git-исходников не означает сборку или
установку нового решателя. Исходные данные пользователя автоматически не изменены.

## Выполненные проверки

`node --test test/conrabFullNewton.test.js` — 7/7 PASS на Node.js 22.16.0.
Проверены последний номер строки, label, обе Boolean-метки, состав подсказки,
значение при отсутствии поля, независимость двух профилей, все четыре пары
false/true, преобразование профильных колонок и JSONL round trip.

Тест читает реальную декларацию схемы, но вместо createSchema использует
identity-функцию в VM, чтобы не требовать Vite-разрешение импортов. Сериализатор,
преобразование профильных колонок, форма массивов и Boolean-форматтер взяты из
исходников проекта; их локальные копии сверены по Git blob SHA. Это проверка
декларации/преобразования данных, не запуск полного приложения в браузере.

Полный npm test, Vite build, browser smoke test и развёртывание не выполнялись.
package.json и две корневые записи package-lock.json синхронно обновлены
4.25.0 → 4.26.0; версии и целостность зависимостей не изменялись (проверено diff).
Нужны полная сборка и визуальная проверка строки/подсказки в обеих колонках,
проверка Undo/Redo и сохранения настоящего задания. PR не означает
автоматическую публикацию или слияние в main.
