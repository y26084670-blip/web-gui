## Назначение

Документ является единственным владельцем команд, матрицы проверок, критериев
приёмки и сохранённых свидетельств. Он строго различает:

- проверку, требуемую для конкретного изменения;
- фактически выполненную проверку текущей ветки;
- исторический результат другого коммита;
- пользовательское подтверждение реального сценария;
- ещё не выполненную проверку.

Наличие теста или команды не означает, что они были запущены. Успешная сборка
не подтверждает интерактивное поведение браузера.

## 1. Среда

Каноническая CI-среда задаётся `.github/workflows/agent-check.yml`:

- Node.js 24;
- чистая установка `npm ci`;
- Ubuntu и Windows;
- production-сборка `npm run build:release`;
- `npm test` только при ручном `workflow_dispatch` с `run_tests=true`.

Для локального воспроизведения требуется актуальный Node.js 24 и зависимости,
соответствующие `package-lock.json`. Браузерные проверки полной функциональности
проводятся в актуальном Google Chrome Desktop или Microsoft Edge Desktop через
HTTPS либо `localhost`. Файловые сценарии требуют File System Access API и
разрешений выбранного каталога.

Интеграционные проверки запуска Clark требуют Windows, установленной актуальной
поставки Clark, зарегистрированного обработчика `clark://`, доступного
`mpiexec.exe` и тестового дерева `clark.projects`.

Из корня репозитория:

```powershell
npm ci
npm test
npm run build:release
npm run build:pages
npm run assets:verify
npm run dev
```

| Команда | Подтверждает | Не подтверждает |

## 5. Ручные сценарии приёмки

### 5.1. Базовое редактирование

1. Открыть приложение в безопасном контексте.
2. Выбрать каталог проектов, проект и задание.
3. Загрузить модель и проверить вкладки, связанные представления и диагностику.
4. Изменить данные, проверить dirty-индикацию, Undo/Redo и предупреждение при
   смене задания.
5. Сохранить, повторно загрузить и сравнить существенные данные.
6. Убедиться, что `_nogo.e3d` удалён только после успешной записи и свежей
   проверки без ошибок.

### 5.2. Материалы и импорт

Проверяются базовые readonly-библиотеки, локальные библиотеки задания,
независимые ревизии и история, импорт legacy ФММ/ВТСП, графики, удаление и
корректность ссылок `xapName`.

### 5.3. 3D и генераторы

Проверяются открытие/закрытие modeless-окна, изменение размера, осевые виды,
fit, видимость, picking, симметрии, дискретизация, выбранный момент, движение,
амплитуды и источники. Для генератора проверяются формула, диапазон, preview,
история, применение и сохранение соответствующего файла.

### 5.4. Примеры и демонстрация

Проверяются установка с прогрессом и отменой, пропуск существующих файлов,
имена с `#` и `=`, демонстрационная копия в памяти, запрет сохранения демо и
восстановление исходных данных при повторной загрузке.

### 5.5. Интеграция Clark

Проверяются формирование `clark.tasks.txt`, включение и отключение строк,
повторное связывание каталога, запуск решателя, клиента цепи и импорта,
ограничения REAL64 и одного задания для цепи, а также чтение `_summary_out.txt`.

## 7. Требования к свидетельству

Для фактически выполненной проверки фиксируются:

1. commit или точный рабочий diff;
2. среда: ОС, Node.js, браузер и, при интеграции, версия Clark;
3. команда или последовательность действий;
4. итоговые количества pass/fail либо наблюдаемый результат;
5. существенные предупреждения и ограничения;
6. область, которую результат не подтверждает.

Фразы «тесты есть», «раньше работало», «сборка прошла» и анализ исходников без
этих сведений не считаются полным свидетельством.
