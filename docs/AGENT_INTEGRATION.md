# Локальный помощник редактора

Обновлено: 2026-09-06 15:24 UTC.

## Граница

Редактор собирается самостоятельно. Встроенные короткие правила и 18 справочных
тем не требуют установленного clark.agent. Отдельный локальный агент подключается
через WebSocket; источником ответа явно отмечается агент либо встроенная помощь.
Агентские действия не исполняются. Подсказка начинается с выбора базового каталога.

Владелец AgentState, RPC и локальной памяти — репозиторий clark.agent:
`docs/STATE_PROTOCOL.md`, `docs/WEBSOCKET_PROTOCOL.md`, `docs/MEMORY_MODEL.md`.
Клиент использует RPC версии 2; приложение и схема состояния имеют собственные версии.

## Локальная разработка

В соседнем репозитории агента:

```powershell
npm ci
npm start -- --allow-origin http://localhost:5173 --allow-origin http://127.0.0.1:5173
```

В редакторе:

```powershell
npm ci
npm run dev
```

Откройте `http://127.0.0.1:8765/settings`, получите ключ редактора и вставьте его
в блок «Подключение локального агента» правой панели. Адрес по умолчанию —
`/agent/rpc`. Vite проксирует только этот маршрут на `127.0.0.1:8765/rpc`.
Ключ передаётся в hello, а не в URL; он хранится только в памяти и sessionStorage
текущей вкладки. Отключение удаляет настройку вкладки. Администрирование памяти
не доступно через этот ключ или прокси редактора.

Для preview используйте порт 4173 и явно разрешите соответствующий origin в агенте.
При недоступном агенте ввод вопросов и редактор продолжают работать. Восстановление
связи происходит автоматически после корректного первоначального подключения.
Запоздавшие ответы для прежней задачи не меняют подсказку новой задачи.

## Локальный HTTPS

Отдельная конфигурация `deploy/caddy/Caddyfile.local` использует
`https://localhost:8443`, bind 127.0.0.1 и переменную CLARK_GUI_ROOT с корнем проекта.
Она запускается установленным Caddy отдельно от LAN-конфигурации. Сертификат
локального центра Caddy должен быть доверенным. В агенте разрешается точный
origin `https://localhost:8443`. Маршрут `/agent/rpc` использует WSS и не проксирует
административные API. Не заменяйте им общую LAN-конфигурацию автоматически.

## Удалённая раздача

Существующая LAN-конфигурация не изменена. При открытии GUI через адрес LAN
в этом инкременте доступна встроенная помощь; отдельный агент не подключается.
Это исключает неявное сохранение данных нескольких клиентов в общей БД сервера.
Подключение удалённо раздаваемого GUI к машине пользователя требует отдельной
проверки браузерных разрешений и защищённой маршрутизации.

## Сборка и проверки

Команды dev/build больше не копируют исходники агента. `agent:clean` удаляет
только устаревшие `.generated/clark-agent` и `dist/clark-agent`. Подготовка и
проверка `data/default` сохранены. Node.js нужен для сборки, а отдельный агент
для базовой работы редактора не нужен.

CI для PR и main выполняет `build:release` без соседнего приватного репозитория
на Linux и Windows. Тесты не запускаются автоматически; при необходимости
доступны отдельная команда `npm test` и параметр `run_tests` ручного запуска
workflow `Build editor and agent fallback` (по умолчанию выключен).
Проверки выбираются по риску изменения. Для изменений взаимодействия с агентом
может потребоваться сквозная проверка реального клиента, сервера и SQLite;
mock-тесты транспорта и статические контракты не заменяют её.

Изменения согласования ведутся в отдельной ветке и draft PR; main обновляется
только после отдельной команды пользователя. Сведения о проверенном инкременте
и незавершённых работах уточняются в resume.md.
