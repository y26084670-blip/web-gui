# Локальный помощник редактора

Обновлено: 2026-09-08 11:47 UTC.

## Текущее состояние: 4.12.0

Правая панель полностью отключена: элементы управления недоступны, автоматическое
подключение к агенту и RPC-вызовы не выполняются. Встроенная помощь также неактивна.
Статус панели:

> Агент отключен. Встроенный помощник [Экспериментальный: пока ничего не работает]

Это состояние задано `PANEL_DISABLED = true` в `TaskAgentPanel` и одинаково для
локального запуска, GitHub Pages и раздачи через LAN. Отдельный агент не нужен
для работы редактора.

Клиент агента, встроенные правила, 18 справочных тем и настройки прокси сохранены
для дальнейшей интеграции. Описанные ниже сценарии подключения применимы только
после отдельного согласованного включения функциональности; в текущем релизе
запуск агента сам по себе не активирует панель.

## Сохранённая граница интеграции

Редактор собирается самостоятельно. В сохранённом сценарии локальный агент
подключается через WebSocket; источником ответа отмечается агент либо встроенная
помощь. Агентские действия не исполняются. Подсказка начинается с выбора базового
каталога. Встроенные правила и справочные темы не требуют установленного
clark.agent, но сейчас недоступны вместе со всей панелью.

Владелец AgentState, RPC и локальной памяти — репозиторий clark.agent:
`docs/STATE_PROTOCOL.md`, `docs/WEBSOCKET_PROTOCOL.md`, `docs/MEMORY_MODEL.md`.
Клиент использует RPC версии 2; приложение и схема состояния имеют собственные версии.

## Сценарий локальной разработки после включения

В соседнем репозитории агента:

```powershell
npm ci
npm start -- --allow-origin http://localhost:5173 --allow-origin http://127.0.0.1:5173
```

В редакторе:

```powershell
npm ci
npm run dev
```

После согласованного включения панели ключ редактора получают по адресу
`http://127.0.0.1:8765/settings` и вводят в блок «Подключение локального агента».
В версии 4.12.0 поле ввода отключено. Адрес по умолчанию —
`/agent/rpc`. Vite проксирует только этот маршрут на `127.0.0.1:8765/rpc`.
Ключ передаётся в hello, а не в URL; он хранится только в памяти и sessionStorage
текущей вкладки. Отключение удаляет настройку вкладки. Администрирование памяти
не доступно через этот ключ или прокси редактора.

Для preview предусмотрен порт 4173 с явным разрешением соответствующего origin
в агенте. Сохранённый сценарий предусматривает ввод вопросов при недоступном
агенте и автоматическое восстановление связи после корректного первоначального
подключения. Запоздавшие ответы для прежней задачи не меняют подсказку новой
задачи. При отключённой панели эти механизмы не запускаются.

## Сценарий локального HTTPS после включения

Отдельная конфигурация `deploy/caddy/Caddyfile.local` использует
`https://localhost:8443`, bind 127.0.0.1 и переменную CLARK_GUI_ROOT с корнем проекта.
Она запускается установленным Caddy отдельно от LAN-конфигурации. Сертификат
локального центра Caddy должен быть доверенным. В агенте разрешается точный
origin `https://localhost:8443`. Маршрут `/agent/rpc` использует WSS и не проксирует
административные API. Не заменяйте им общую LAN-конфигурацию автоматически.

## Удалённая раздача

Существующая LAN-конфигурация сохранена. При открытии GUI через адрес LAN
в версии 4.12.0 вся правая панель отключена, встроенная помощь недоступна,
отдельный агент не подключается. Неявного сохранения данных клиентов через
панель в общей БД сервера не происходит.

Для будущего включения подключения удалённо раздаваемого GUI к машине
пользователя остаётся открытым вопрос браузерных разрешений и защищённой
маршрутизации. Публикация редактора сама по себе такой доступ не настраивает.

## Сборка и проверки

Команды dev/build больше не копируют исходники агента. `agent:clean` удаляет
только устаревшие `.generated/clark-agent` и `dist/clark-agent`. Подготовка и
проверка `data/default` сохранены. Node.js нужен для сборки, а отдельный агент
для базовой работы редактора не нужен.

CI для PR и main выполняет `build:release` без соседнего приватного репозитория
на Linux и Windows. Тесты не запускаются автоматически; при необходимости
доступны отдельная команда `npm test` и параметр `run_tests` ручного запуска
workflow `Build editor and agent fallback` (по умолчанию выключен).
При подготовке версии 4.12.0 по указанию пользователя тесты и отдельная
контрольная сборка не запускаются; ручной `run_tests` не включается. Штатные
автоматические workflow сохраняются. Будущая оценка взаимодействия реального
клиента, сервера и SQLite относится к отдельному этапу включения агента;
текущее отключение панели не подтверждает работоспособность этого сценария.

Изменения согласования ведутся в отдельной ветке и draft PR; main обновляется
только после отдельной команды пользователя. Сведения о проверенном инкременте
и незавершённых работах уточняются в resume.md.
